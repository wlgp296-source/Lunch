# Lunch Roulette PRD v0.1

## 1. 서비스 개요

점심 전 사용자의 기분, 식사 기록, 예산, 거리 조건을 반영해 중복되지 않는 메뉴 3개를 추천하고, 선택한 메뉴의 주변 식당을 찾아주는 웹 서비스입니다.

혼자 사용할 수도 있고, 팀원들이 초대 링크로 참여해 메뉴와 식당에 투표할 수도 있습니다.

## 2. 타깃 사용자

- 혼자 점심을 먹는 직장인
- 여러 명이 함께 점심을 먹는 회사 팀
- 대학생
- 식단·건강 관리를 원하는 사용자

## 3. 핵심 문제

- 매일 점심 메뉴를 고르기 귀찮음
- 최근 먹은 메뉴와 겹치는 것을 피하고 싶음
- 예산과 이동 거리에 맞는 식당을 찾기 어려움
- 여러 명의 의견을 모으기 어려움

## 4. 플랫폼

- 모바일 우선 반응형 웹
- 회원가입 없이 사용
- 현재 위치 또는 주소 입력 지원
- 팀원은 초대 링크와 닉네임만으로 참여

## 5. 사용자 입력

기본 입력:

- 오늘의 기분: 복수 선택
- 최근 먹은 메뉴: 메뉴 검색 후 선택
- 인원
- 예산
- 이동 가능 거리
- 현재 위치 또는 주소

추가 개인 설정:

- 알레르기
- 먹기 싫은 음식
- 개인 식사 기록

알레르기와 먹기 싫은 음식은 추천에서 항상 제외합니다.

## 6. 메뉴 추천

- 메뉴 카테고리는 JSON 데이터로 관리
- 기본 카테고리:
  - 한식
  - 중식
  - 일식
  - 분식
  - 양식
  - 치킨·패스트푸드
  - 샐러드·건강식
  - 기타
- 카테고리 다양성은 강제하지 않음
- 조건 적합도가 높은 메뉴 3개 추천
- 이전에 먹은 메뉴는 기본 제외
- 사용자가 원하면 `다시 먹고 싶어요`를 선택해 추천 허용
- 세 메뉴가 모두 마음에 들지 않으면 새로운 메뉴 3개로 갱신

팀 추천 시:

- 모든 팀원의 조건을 만족하는 메뉴를 우선 추천
- 모두를 만족하는 메뉴가 없으면 가장 많은 팀원의 조건에 맞는 메뉴 추천
- 일부 팀원만 입력해도 대표자가 추천 결과 생성 가능
- 결과에 현재 응답 인원 표시

## 7. 식당 추천

메뉴 후보 중 하나를 선택하면 해당 메뉴의 주변 식당을 최대 3곳 보여줍니다.

식당 정보:

- 식당명
- 대표 메뉴와 가격
- 거리·예상 이동 시간
- 주소
- 영업 여부
- 평점·리뷰 수
- 지도·길찾기 링크
- 메뉴 추천 이유

실제 지도·장소 API를 연동합니다.

## 8. 팀 기능

팀 점심방 흐름:

1. 대표 사용자가 점심방 생성
2. 초대 링크 공유
3. 팀원이 닉네임으로 참여
4. 각자 기분과 최근 먹은 메뉴 입력
5. 대표자가 공통 조건 입력
6. 메뉴 추천 및 투표
7. 메뉴 선택 후 식당 추천 및 투표

투표 기능:

- 여러 메뉴·식당에 복수 투표 가능
- 투표 후 언제든 변경 가능
- 투표 결과는 실시간 반영
- 동점인 메뉴·식당은 모두 표시
- 동점 발생 시 `동점입니다` 알림 표시
- 이후 룰렛으로 최종 후보 결정

룰렛은 서버에서 결과를 먼저 확정하고, 참여자 화면에는 같은 결과를 향해 돌아가는 애니메이션을 보여줍니다.

## 9. 기록 기능

개인 기록:

- 사용자가 선택한 메뉴 자동 저장
- 식당 선택 시 `먹기로 한 메뉴`로 저장
- 이후 `먹었어요`로 확정 가능
- 기록은 다음 추천에서 중복 제외에 활용
- 원하면 다시 추천 대상으로 허용 가능

팀 기록:

- 날짜
- 참여자 닉네임
- 추천 메뉴
- 최종 메뉴
- 선택한 식당
- 투표 결과

팀 히스토리는 같은 점심방 참여자만 볼 수 있습니다.

## 10. 데이터·기술 원칙

코드 처리:

- 메뉴 중복 제외
- 알레르기·싫어하는 음식 필터링
- 팀원 조건 통합
- 예산 필터링
- 거리 정렬
- 투표 집계
- 룰렛 랜덤 결과 결정

LLM 처리:

- 메뉴 추천 이유
- 오늘의 메뉴 소개 문구
- 팀 조건을 반영한 자연스러운 설명

저장 방식:

- 익명 사용자 ID
- 데이터베이스에 개인 설정·식사 기록·팀방·투표 저장
- 로그인은 필수가 아니며, 추후 선택적으로 추가

## 11. 후속 결정 사항

- 지도·장소 API 종류
- 세부 화면 디자인
- 메뉴 JSON의 실제 항목
